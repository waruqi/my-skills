# 源码组织、调用关系与通信

先解释源码放在哪里，再解释运行时怎样合作。根据工作区清单、包导出、启动入口、构建脚本和实际目录生成仓库组织图：根目录负责什么，各包为何分开，包内入口、实现、适配器、测试、示例、文档、资源与产物在哪里。只画实际存在的目录，区分声明的路径模式与磁盘目录。生成代码标明生成来源；实验实现与正式入口分别解释。目录树不是运行分层，也不能直接充当课程顺序。

整体职责图之后插入仓库与包组织图；进入某个模块时再展开内部源码组织。让读者知道要改一个具体行为应从哪个文件、入口和测试开始。节点连接模块讲解及相关真实代码；包清单适合证明导出和依赖，不能冒充行为实现。支持文件树自由查阅，同时保留连续翻页。

从实际入口追踪代表性路径，补充对象持有关系和函数调用图。分别标注创建、持有、继承、接口实现、普通调用、回调、事件和导入依赖。指出谁拥有状态、如何初始化及释放、哪些实现由调用方注入。静态导入只能证明依赖，不能证明运行时调用或所有可能目标；没有语义索引时不宣称完整引用分析。

用同一个任务对照函数参数、返回值、Promise 完成值、事件与最终用户输出。记录必填与可选参数、默认值、数据生产者和消费者，展示小而对应的输入输出及必要的中间变化。说明错误、取消和重试怎样改变结果。公开函数返回 void 并不意味着没有输出，最终数据可能通过事件或共享状态传递。长协议和完整记录按需打开，关键字段直接可见。

通信边界按源码分别核对：进程内调用、线程消息、子进程管道、标准输入输出、HTTP、WebSocket、TCP 或其他实际协议。写清两端角色、编码与分帧、请求关联标识、流式事件、完成条件、超时、取消及关闭行为。应用消息格式与底层传输分别解释；通过命令调用远端程序，不等于本文件直接实现 TCP。可替换传输不应被写成唯一部署方式。教学帧、源码推导和真实抓包明确区分。

资源访问沿调用标到具体适配器：文件路径相对哪里，配置从哪里来，数据库或网络资源由谁打开，句柄与连接由谁关闭。未读实现不能仅凭名称补全行为。覆盖主要包的组织方式与关键路径，同时明确哪些只核对了目录和公开契约、哪些完整读过实现，不把离线源码快照称为完整源码审计。

源码图穿插在对应模块与动画之间：先局部组织与对象关系，再跟随调用看数据，最后解释边界与设计取舍。不要把所有源码专题放到课程末尾。插入按稳定页面或图标识定位，重跑不重复；更新前后页衔接，并在最终课程上实际验证入口、片段与完整文件一致。

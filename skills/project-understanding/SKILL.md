# 项目理解

让用户用尽量少的时间建立正确的整体认识，再沿图进入实现细节，最终能理解关键代码。默认输出到目标项目的 `architecture-guide/`，按用户语言编写。技能只保留通用方法、格式和渲染器；项目名称、路径、标识、架构和结论全部从目标项目提取，写入项目输出。

## 建立证据

读取仓库约定、README、构建配置、清单、公开入口和关键实现。确定项目名、用途、技术栈、部署单元、模块及运行入口；名称冲突时说明依据，无正式名称时明确采用目录名。不能带入技能仓库或上次分析项目的信息。

覆盖全部主要模块，区分正式实现、可选集成、实验代码和计划。先跟踪一条具体用户操作，再扩展其他主要运行路径。每个边界记录生产者、消费者、数据类型、样本和源码位置。完整阅读涉及结论的文件，截断输出不算完整阅读；纳入源码快照不等于逐行审计。

更新已有分析时比较源码摘要和版本，复用仍然有效的证据，重新检查受影响的结论。说明覆盖范围和未验证部分，不编造细节填满页面。

## 先让人看到项目能做什么

首页先用一句具体的话说明谁会用它、拿它完成什么事、结果在哪里。选一个小而完整的场景，把用户输入、运行中的界面、最终产物和修改前后放在一起。第一张图画这件事怎样完成，先写动作和结果，再标模块名；不要以包分组、设计术语或阅读指南开场。库和后台服务也应展示最小调用及可观察结果，不强造界面。

从首页的图进入可照做的快速体验：前提条件、在哪个目录执行、完整命令、所需配置、成功时看到什么，以及常见失败如何定位。分清安装成品、从源码启动和服务部署；只写项目实际需要的路径。优先采用仓库截图或本地捕获，说明版本和来源。示意界面、预期结果、真实运行分别标注；未经执行不能写成已验证。不给首次体验塞入整套开发流程。

## 连续讲解优先

默认首页是一套可逐页观看的讲解，使用 lesson.slides 编排：先说明项目用途与可见结果，再用同一个任务串起启动、整体架构、运行过程、相关设计和关键源码，最后展开可选模块。核心设计和动画在解释对应行为时出现，不要求用户先读完多个独立栏目。每页只讲一个问题，写出承接上一页的讲解，以及下一页要看的内容；不要仅把页面树排序后自动当成课程。

参考演示文稿的阅读节奏：标题写本页要解释的具体行为，左侧以大图呈现关系或变化，右侧给出结论和必要解释。设计原因优先画成“遇到的问题 → 实际机制 → 可观察结果”，执行过程画成输入经过哪些处理后产生输出；不同语义用一致的颜色区分，不能把模块名清单装进方框冒充关系图。每页保留一条可由源码支持的关键结论，留白服务于阅读，文字和连线在普通笔记本视口中应清晰可辨。参考用户截图时提取信息组织方法，不复制示例项目的名称、架构或结论。

每页以一张图或局部动画为主，旁边有简短讲解。核心设计页直接展示经过选择的关键源码片段、真实行号、语法着色和说明：指出决定行为的条件、状态或返回值，解释为什么需要它；完整源码和长数据按需打开。动画可以按步骤范围分成几页，在合适的位置穿插设计和代码讲解，阶段内不能丢失上下文。

提供前后翻页、章节选择、模块跳转、返回原讲解位置、全屏和资料模式。图节点能继续下钻；自由查看后能回到刚才进度。全屏使用浏览器接口并处理拒绝，不把隐藏侧栏冒充真正全屏。文字讲解始终可用；可选本地语音朗读，不依赖在线 TTS。翻页、离开页面和后台时停止播放及朗读。提供键盘操作，不抢占源码输入框与动画进度条的按键。

动画默认仅显示一条紧凑工具栏：播放、前后步进、进度和计数；调速、阶段选择与重播放进设置。讲解和数据放在图旁，不能继续在图上方堆长段落、警告和多行控件。桌面优先在一个视口内展示图与讲解，手机允许上下布局。资料模式保留文件树、源码、Git 和原有完整分析。

讲解不能在入门概览结束。后续按目标项目的父子模块关系串联子架构、模块和关键实现，每页明确下一页内容及其与当前页的关系；进入任意模块仍能继续翻页。固定提供首页、返回刚才页面、上一页和下一页。关键实现单独选取短代码片段并讲解，不仅给源码链接。详情必须不透底地覆盖整个视口，能返回原页；源代码弹层仍可操作。工具条采用紧凑控件，次要操作折叠，默认尽量放大图并可暂时收起讲解。

## 由浅入深

首页只回答项目做什么、输入来自哪里、主要能力如何合作、结果去哪里。用少量有意义的系统边界组织总图，不把全部类和文件塞进首页。点击子系统后再看该层的组件关系；进入模块后再看职责、运行和实现。小项目可以省略不必要的层级，不能发明不存在的子系统。

每页固定为：简短标题和所在层级、当前层架构图、当前页讲解。图和侧栏共同导航。提供可收起的侧栏，分为按页面父子关系组织的架构导览树和按真实路径组织的项目文件树；支持文件名/路径搜索、当前位置与相关文件标记，以及代码到架构讲解的返回链接。面包屑仅表示祖先路径，帮助返回上层。所有页面必须从首页的图逐层可达。

连线必须区分调用、返回、数据流、依赖和职责分解。下钻节点直接进入子页；当前页节点可定位下方解释、数据或代码。根据问题选用系统边界图、组件图、时序图、数据变化图或状态图；不能只把列表改成方框排列。

每个模块讲清六件事：是什么及解决什么问题；设计原因和代价；实际如何运行；输入的生产者、格式、字段含义与样本；输出的消费者、格式、错误与样本；对应源码和关键逻辑。用具体情景串联，术语在出现处解释。不能执行的样本注明“教学示意”；不适用的输入输出说明原因，不伪造接口。

模块图下直接展开一组有对应关系的输入、处理和输出：谁给出参数，当前模块改变了什么，谁拿到结果。短样本和关键字段解释必须可见，长记录留作进一步核对。用同一任务贯穿相邻模块，标明摘录省略了什么；不能把所有 JSON 塞进折叠框就算讲清数据流。

## 找出值得先理解的核心设计

在用途和快速体验之后，提炼这个项目最值得先抓住的设计主线。不要停在包划分、分层、插件化等通用描述，也不要强求每个模块都有“独创”。从关键状态如何保存、数据如何变形、能力如何隔离、失败如何恢复等真实边界寻找候选，按用户理解整个项目的收益排序。重点数量由证据决定，不凑固定数量；证据不足时直说。

对入选设计，完整读相关实现与测试或设计记录，回答一个反事实问题：如果换成最简单的实现，具体哪种行为、约束或成本会改变？用一条小轨迹说明触发条件、输入、状态变化和可观察结果，再解释选用机制、代价与不适用场景。动机有注释或设计记录时引用；仅由代码推导时标为分析判断。不要把结构推断写成作者意图、实测性能或行业唯一性；未经外部证据核实，称“代表性设计”即可。

核心设计整合进连续讲解，不另设与课程竞争的专题导航；图中仍保留通往相关设计的节点。先用一张图说明几项设计的关系，再分别进入具体实现。专题顶部画具体机制：对照简单方案与当前方案、数据转换、状态推进或故障恢复，而不是把亮点清单装进方框。下方自然展开问题、设计选择、输入输出样本、关键代码和取舍；连到已有模块、运行流程和请求体，不另造孤立的索引页。示意对照明确标注，不能虚构其他项目的行为。

优先用最小本地实验验证决定性差异，保留可复现样本。区分默认路径、可选机制、实验代码和仅文档保证的行为。验收时让读者能说出“这个项目最值得学的设计是什么、没有它会怎样、代码在哪里”，而不是只记住模块名。名称、选择、结论和样本始终从目标项目提取，不能把本次案例写进技能或模板。

## 讲得像带人读代码

用日常技术交流的说法，直接写哪个函数处理了什么数据、为什么需要这样处理。少用“抓住主线、能力编排、边界投影、打通链路”等抽象说法；需要专业术语时先给具体例子，再解释术语。标题优先写行为，例如“消息怎样发给模型”，不要写成口号、悬念或连续反问。不要用“一站、下一站、三个世界”包装阅读顺序。真实性与限制集中放在合适的说明处，避免每段都打断讲解。

先说发生的事，再解释机制和必要性。例如从“读完文件后，程序把内容放回下一轮请求”进入消息结构，而不是从“上下文协议归一化”开始。标题写本段的具体发现，正文用连贯短句，保留必要的技术名并就地解释。不要让每页都重复“是什么、为什么、如何运行”或“输入：来源、格式与样本”的问卷标题；这些是分析检查点，不是给读者看的固定措辞。解释设计时说明没有该机制会遇到的具体问题，再讲选择和代价；区分源码事实与自己的推断。

代码必须融入理解链路。图中的实现节点进入机制与代码页；正文嵌入真实文件的关键片段，解释入口、分支、状态变化和返回值，可继续打开带行号的完整源码。不要只给文件名，也不要默认展示几百行代码。让用户能把行为、数据字段和实现对应起来。

## 运行与数据

优先使用项目已有假实现、临时文件和本地环境复现流程，在真实边界捕获快照，并标明模拟外部响应的范围。不能把模拟样本描述成线上抓包。AI 项目额外展示内部消息、系统指令、工具声明、上下文选择与最终请求体，通过注入传输或发送前回调阻止真实外部请求。其他项目展示对应的请求、任务、存储记录或渲染数据，不强套 LLM 概念。

## 一次完整任务的图解动画

把完整流程动画整合进连续讲解，不另设平行导航。用一个具体任务串起安装、必要配置、启动、用户输入、实际执行、数据变化和最终结果。任务、模块、命令和数据全部从目标项目提取；没有安装步骤的库展示最小调用，不强套命令行或模型工具。不要用多个无关例子拼接，也不要把所有包强行画成一条执行链。未经过的主要模块说明用途，给出另外的图解入口。

使用内容格式中的 walkthrough 播放器，进入页面默认播放，允许暂停、暂停、前后步进、重播、阶段跳转、拖动进度和调速。保持同一张模块图，随步骤高亮当前模块和实际传递数据的连线；旁边同步展示输入、输出、当前文件或界面结果，以及源码入口。图节点可进入已有模块页。每步讲清谁调用谁、哪些字段发生变化；长请求体可展开，但关键差异应直接可见。

优先重新运行最小本地样本，从捕获记录生成步骤，保留更新脚本。安装命令、界面示意、真实执行、测试替身及发送前截获分别标明，不能让动画暗示执行过未验证的流程。播放只展示数据，不执行安装或访问外部服务。动画速度只为阅读，不冒充实际耗时。离开页面、切换后台或打开源码时暂停；尊重减少动态效果的系统设置。

验证播放推进、暂停保持、前后切换时的数据一致性、最后一步自动停止、重新播放、源码和模块跳转、手机布局与无动画页面。用新项目的小样本检查模板没有写死本次案例；格式校验应拒绝不存在的节点、连线、步骤引用和缺失样本。

## 生成与验收

按[内容格式](references/content-format.md)编写 `content.json`。项目元信息、页面树、图、解释、数据和引用全部来自目标项目，模板只做通用渲染。

```sh
python3 <skill-directory>/scripts/build.py --root <repository> --content <output>/content.json --out <output>/dist
```

构建器检查页面层级、图的覆盖与可达性、节点定位和源码引用，它不会自动分析设计原因。运行相关检查和可用的浏览器验证：从首页沿图完成阅读链，返回上层，定位数据与代码，打开完整源码；检查键盘操作、缩放、窄屏、文字遮挡和箭头方向。侧栏与图节点保持同一层级和选中状态，图仍须逐层可达。

验收时先按第一次接触项目的读者来读：首页能否很快说清用途、输入和结果；能否照着启动并认出成功效果；进入任一主要模块能否直接找到一组输入输出，并顺着图追到代码。页面数、图数量和格式校验通过不能代替这些检查。

交付网站入口及覆盖与验证边界，在目标项目 README 记录实际命令。可复用技能在源仓库维护，项目内容和网站留在目标项目。升级旧内容时按层级重新组织证据，不能为通过构建而机械补上无意义的图或段落。

源码阅读应支持离线语法着色、真实行号、引用入口高亮、文件内查找及跳转。构建时从目标仓库解析真实绝对路径，提供原文件和本地编辑器定位；标明快照与当前文件可能不同，不宣称具备语言服务器的定义跳转。

阅读界面默认采用浅色源码主题，分别标示引用入口、当前行和搜索结果。侧栏可由用户收起并在可用时记住选择，窄屏首次访问默认收起；头部高度变化时避免遮挡导航。

## Git 历史与架构演进

侧栏提供独立 Git 历史入口。默认分析最近约三个月，只读取本机 Git，不切分支、不自动 fetch。日志、作者/提交时间、父提交、分支 tip 与实际 diff 作为事实；从行为变化、接口边界和故障修复中挑选关键提交，读提交说明和相关 diff 后再写原因、影响与架构关联。只有路径命中时标为文件关联，不把它当作设计分析；未解读提交明确说明。历史代码不跳到当前文件同号行冒充旧版本。

数量和大文件限制必须可见。差异按需离线加载，展示增删行号及统一/左右视图，处理根提交、合并第一父提交、重命名、删除与二进制。分支比较说明是 tip 净差异还是 merge-base 差异，显示范围与本机引用新鲜度。关键解读属于项目 content.json，技能和模板不得写死提交、分支或项目模块。

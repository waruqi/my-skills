# 索引和讲解格式

`analysis.json` 为 UTF-8 JSON，项目内容只放被分析项目中。最小结构：

```json
{
  "title": "从项目提取的名称",
  "intro": "用具体行为说明源码职责及本次深入分析的范围。",
  "start": {"file": "src/entry.ts", "symbol": "handleRequest"},
  "notes": [{
    "file": "src/entry.ts",
    "symbol": "handleRequest",
    "title": "解释这个函数改变了什么",
    "summary": "一至两句说明本函数的作用和关键行为。",
    "body": "根据实际源码说明调用过程、关键分支和状态变化。",
    "commentTranslation": "有原注释时，提供经实现核对的中文解读；无注释则省略。",
    "input": {"示意字段": "由实际接口确定"},
    "output": "返回给谁、格式与含义",
    "design": "有证据的设计原因；分析推断明确标注。",
    "failure": "错误、取消、重试与资源释放语义。",
    "evidence": "源码推导 / 已运行捕获 / 文档契约"
  }],
  "chains": [{
    "title": "一条具体用户操作的调用路径",
    "summary": "说明路径的起点、结果和验证范围。",
    "steps": [{
      "file": "src/entry.ts",
      "symbol": "handleRequest",
      "title": "当前步骤发生的事",
      "relation": "入口 / 直接调用 / 回调触发 / 跨进程协议 / 相关实现",
      "text": "本步数据如何进入与离开，为什么接下来阅读下一个符号。"
    }]
  }]
}
```

以上文件名与函数仅说明结构；创建分析时替换为真实文件及唯一声明。`symbol` 可以是 `Class.method` 等完整归属名。重载优先定位有函数体的实现；仍有多个候选时加真实 `line` 区分。其他语言用 `file + line` 提供人工锚点，不伪造符号 ID。构建器拒绝缺失文件、符号歧义和越界行号；只有锚点仍在不能证明讲解仍正确。

`summary` 显示在真实函数声明上方；`body`、`input`、`output`、`design`、`failure` 在右侧详细讲解中显示。摘要不要机械重复标题或堆满细节，保留一个明确的详细讲解入口。`commentTranslation` 为经核对的中文解读，代码区默认折叠、右侧完整展示；原文优先取该符号索引中的 `doc`。普通 `//` 注释未被索引器提取时，可用 `commentOriginal` 提供真实原文，不能编造。重载、同名方法和继承注释必须确认归属。缺少人工解释的符号显示“暂无人工深入讲解”，可继续读源码文档注释与自动关系，不用占位文案填满。

## 机器索引

构建输出 `index.json` 供核验，`data.js` 供离线页面加载；源码内容、着色区间和标识符定位放在 `chunks/`，按文件加载。浏览器不使用 fetch 读取本地文件，可通过 file URL 打开。

- `files`：相对路径 ID、SHA-256、行数、语言、可读性、源码块和符号 ID。
- `symbols`：文件位置、起止行、类型、父符号、完整名称、签名、源码文档注释；ID 使用路径与 AST 起始偏移，只在本次快照中稳定。
- `refs`：文件、行、UTF-16 列、长度、候选目标符号、所属函数或类。不含声明自身，不等于全文文本命中。
- `calls`：调用位置、调用表达式、所属符号、目标列表、是否构造、是否位于未命名回调内。`static` 是编译器绑定，不保证运行时唯一目标；`contract` 指向接口或声明；`unresolved` 包括动态表达式、外部依赖或未收录目标。
- `inheritance`：`extends` 或 `implements`，方向由派生类型指向基类型。
- `imports`：当前文件到被依赖文件；未收录或无法解析的模块保留 specifier 和空目标。
- `coverage` 与 `diagnostics`：收录范围、未知调用数、配置或语法诊断。不是完整项目类型检查报告。

图默认局部一层，可展开两层，默认最多 13 个节点，分批展开至 61 个；使用固定像素尺寸和滚动区域，不自动缩小字号。右侧关系列表保留真实调用位置，显示超过 600 处时标明截断。全局搜索列表限制 250 个文件/符号；全文搜索达到 300 处后停止并显示实际扫描范围。不能把界面截断当索引中没有更多关系。

## 文件介绍与关键文档

`manualCalls` 可补充不支持语义索引的语言：每条包含 `from: {file,line,name}`、`to: {file,line,name}`，以及调用位置 `file`、`line` 和可选 `note`。节点跳转声明，连线提示调用证据；仅展示当前锚点的一层已核对关系，不声称全量调用分析。构建器校验锚点有效，但正确性仍需要阅读实现。

`gitNotes` 数组每项为 `{commit, summary, files: [{file, summary}]}`，commit 使用完整 SHA 或 `working`。整体摘要解释问题、行为改变和架构关联；文件摘要解释各文件在修改中的作用。构建器通过 `scripts/history.mjs` 导出本地 Git 快照，按提交分块加载。工作区与 HEAD 比较，包含暂存和未暂存的已跟踪文件，不包含未跟踪文件。合并提交与第一父提交比较；重命名按删除和新增分别展示。超过三个月、40 个提交、每提交 100 文件、每文件 100 KB 或每提交约 2 MB 的部分明确标记未收录。`assets/history-view.js` 展示安全转义的真实补丁与双层说明。

`fileNotes` 是文件介绍数组，每项包含 `file`、一句职责 `summary`，以及介绍主要声明、合作关系和阅读顺序的 `body`。代码视图文件开头显示它，不改变真实行号。无人工介绍时只自动提取顶层声明并标注尚未深入分析。

`documents` 是文档翻译数组，每项包含 `file`、中文理解 `summary`、完整 Markdown 译文 `translation`、对应原文件字节的 SHA-256 `sourceHash`，以及可选 `related: [{file, line, title}]`。路径均为被分析仓库内相对路径。构建器检查文件、摘要、译文、原文哈希和关联行号。命令和代码块不翻译；原文段落译文与中文分析分开。当前安全渲染器支持标题、段落、行内代码、代码块和链接，复杂表格可改成逐项说明；不执行原始 HTML。缺少译文时明确显示未翻译，不能自动生成占位译文。

当前编译器程序把所有收录 JS/TS 文件按一个根配置组织。项目引用、不同子项目 paths、运行时注册表、代理对象、动态插件和字符串事件路由需要人工补充或专门分析适配器。函数值经过变量和回调传播时不宣称完整数据流分析。
